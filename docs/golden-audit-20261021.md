# Аудит перед следующим образом Cubie A7A — 21 октября 2026

Статус: аудит завершён; перечисленные ниже исправления подготовлены в исходниках.
Новый образ ещё не собран. Это не заключение о полной готовности к эксплуатации.
Действующие настройки, деньги, службы и карты памяти не изменялись.

## Подтверждённые проблемы

1. **Блокирует самостоятельную установку.** Очистка образа записывает
   `.hardware-profile=factory-only`. `start-post.sh` намеренно запускает интерфейс
   без I/O. `InstallDevice.vue` сохраняет запрос типа, но не применяет профиль;
   `InstallPage.vue` требует `io_ready` для завершения. В результате исправное
   подключённое оборудование не позволяет закончить мастер без SSH. Это
   воспроизвелось на посту 3. Нужна явная операция применения оборудования в
   мастере через ограниченный привилегированный агент, с проверкой простоя,
   состояния операции и безопасного OFF. Автоматически включать выходы нельзя.
2. **Восстановление после ошибки профиля.** `apply-device-profile.sh` останавливает
   wash-engine, затем выполняет команды с `set -e` без обработчика восстановления.
   Ошибка проверки Modbus или compose может оставить backend остановленным.
   Временный `commission-hardware.py` восстанавливает его в `finally`, но прямой
   вызов основного скрипта такой защиты не имеет. Нужна защита в самом основном
   пути и проверка восстановления при отсутствующем/неисправном Modbus.
3. **Поворот в уже выданном образе.** Vendor HDMI toggle сбрасывал поворот после
   начала сессии. Исправляющий ExecStartPost уже есть в текущем коде санитарной
   подготовки и применён отдельно на постах 2/3; выданный Windows IMG его ещё не
   содержит. Включить в следующий выпуск; проверить холодный старт и перезапуск
   графической сессии, включая совпадение сенсора с кнопками.
4. **Старый комплект сборки.** Ранее выданный большой ZIP содержит старый метод
   заполнения свободного места, упавший на ENOSPC. Текущий код использует offline
   zerofree и проверку результата; успешный IMG получен отдельным recovery-путём.
   Следующий комплект нужно выпускать целиком, без необходимости recovery.

## Ограничения, которые надо проверить до выпуска

- Привязка к `/dev/ttyUSB0` в compose и проверках: перестановка или добавление USB
  может выбрать другой адаптер. Нужна инвентаризация USB и затем выбор стабильного
  пути (by-id, либо физического by-path при отсутствии уникального serial).
  Ошибка назначения на текущих платах не доказана.
- Сухой туман требует согласованного общего кошелька и типа в инвентаре главного
  поста. При добавлении поста 3 мастер должен объяснять этот порядок и причину
  отказа; не обходить финансовые ограничения ради завершения установки.
- Расширение раздела до размера новой карты: код и отдельные проверки существуют,
  фактический размер файловой системы новой платы после первого запуска ещё не
  подтверждён в этом аудите. Ошибка grow сейчас печатается и откладывается до
  следующего старта; установщику нужен понятный результат проверки диска.
- 32 GB CL3566-A требует отдельного образа ОС и аппаратного испытания. Текущий
  образ предназначен для Cubie A7A, не является универсальным образом Linux.
- Длительный рост БД/логов, обрыв питания в момент первой загрузки, полный цикл
  сброса и повторной настройки в этом аудите физически не испытывались.

## Подготовленные исправления

`InstallHardware.vue` добавляет действие на шаг «Запуск». Запрос идёт через
закрываемый после установки commissioning endpoint в локальный root-only агент.
Агент принимает только фиксированное действие, не произвольные команды/пути.
На хосте повторно проверяются незавершённая установка, отсутствие сеанса/денег
и реальные устройства. Выбранный тип и ограничения кошелька проверяет существующий
профильный скрипт. Этот путь не содержит команд сброса или изменения денег.

Пока backend перезапускается, мастер хранит квитанцию операции в sessionStorage
и опрашивает статус после восстановления связи. При ошибке позволяет повторить
проверку; завершение установки по-прежнему требует Modbus и совпадения типа.
Профильные команды сериализуются flock. EXIT/TERM/INT/HUP восстанавливают запуск
backend при ошибке после остановки; аппаратная готовность при этом не подделывается.
Команды запуска используют локальные образы с `--no-build --pull never`.

Будущий Windows-сборщик сохраняет отдельный V2 IMG и предлагает balenaEtcher;
старый IMG не перезаписывается. Текущий offline cleaner уже включает hook
восстановления поворота и проверенный zerofree-путь. Ранее выданные ZIP/IMG
изменениями исходников не обновляются и не объявляются исправленным выпуском.

Проверки V2: 21 тест golden tooling, 9 тестов системного агента/профиля,
17 тестов API установки/обслуживания; браузерный сценарий мастера с отказом,
повторной попыткой и временным HTTP 502; production-сборка UI. Проверены загрузка
всех пяти ARM64 образов в пустой отдельный Docker и запуск нового backend с чистой
тестовой БД без подключения к действующим данным. Физическая запись/загрузка V2
ещё не проверена. Комплект не содержит готового IMG: сборка выполняется на Windows
из сохранённого source. WSL-копия V2 хранится отдельно в
`/var/lib/labrix-golden-build-v2`, готовый файл имеет имя
`LABRIX-CUBIE-A7A-GOLDEN-V2-20261021.img`.

### Поправка оценки места V2

Первый запуск на Windows остановился до создания копии: прежний порог требовал
полный логический размер IMG + 4 GiB при наличии 54.17 GiB на C:.
Патч LABRIX-V2-Space-Fix.zip заменяет два helper-файла в папке V2.
SHA-256 исходника вычисляется одновременно с подсчётом ненулевых блоков 64 KiB;
до записи требуется измеренный верхний предел + 24 GiB запаса и на Windows,
и на Linux. Копирование использует ту же гранулярность, O_EXCL, режим 0600,
fsync и последующую полную проверку SHA-256. Исходник не изменяется.
Шесть тестов working-copy прошли, включая trailing hole и Windows-space gate.
Ранее скачанный большой ZIP требует этого патча перед шагом 02.
