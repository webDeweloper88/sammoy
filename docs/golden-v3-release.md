# Golden V3 для Cubie A7A

Выпуск от 22 октября 2026 года. Пользователь подтвердил создание IMG на Windows;
первая загрузка этого IMG для новой мойки ещё предстоит. Репозиторий содержит
исходники и сборочные помощники, без IMG, контейнерных архивов, ключей и данных
рабочих постов.

## Состав

- Мастер первичной установки с применением профиля оборудования и проверкой Modbus.
- Управление одним главным и одним резервным постом: подключение, замена,
  плановая передача, продолжение сохранённой операции и аварийное восстановление
  с явными подтверждениями. Замена 2 → 3 проверена на тестовой мойке.
- Исправление: выполнение и отмена используют адрес нового поста из сохранённого
  плана, даже если его ещё не было в прежнем списке адресов.
- Начальные учётные записи `owner / labrix` и `admin / labrix` с обязательной
  сменой пароля. Linux, БД и инфраструктурные секреты создаются отдельно и уникально.
- Ethernet DHCP, портретный экран HDMI-1/right, минимальная kiosk-сессия,
  генерация идентификаторов и расширение файловой системы при первой загрузке.

`deploy/golden/windows/09-UPDATE-IMAGE.cmd` обновляет только проверенную,
не запущенную V2 WORK-копию в Ubuntu WSL и экспортирует отдельный
`LABRIX-CUBIE-A7A-GOLDEN-V3-20261022.img`. Для запуска нужен полный пакет с
проверенным приложением, пятью ARM64-образами и инструментом zerofree; одних
исходников скрипта недостаточно. Старые экспорты и исходная карта не изменяются.

## Установка новой мойки

1. Записать V3 на предназначенные для новой установки карты двух Cubie A7A.
   При записи содержимое выбранных карт будет заменено. Этот образ не предназначен
   для CL3566-A.
2. На сервере активации создать новую мойку с собственным кодом и выдать отдельный
   код активации каждому посту: 1 и 2. Не использовать активацию старой мойки.
3. Активировать оба поста в одной новой мойке, задать различные сетевые адреса,
   выбрать типы устройств и применить их аппаратные профили.
4. Настроить пост 1 главным, пост 2 резервным, подключить резерв и убедиться,
   что журналы совпадают и оба узла доступны. Telegram настраивать на главном.
5. Настроить лицензию и Click для нового объекта, сменить начальные пароли,
   выполнить проверку оборудования и тесты платежей/NFC.

До подтверждённой связи с реле пост не считается готовым обслуживать клиентов.
Резервирование кошелька можно проверять независимо от реле.

## Проверки перед публикацией исходников

307 unit-тестов backend, 30 проверок golden image, 36 проверок системных скриптов,
16 сценариев управления резервом с отдельными PostgreSQL, загрузка всех пяти
ARM64-образов в пустой изолированный Docker и запуск приложения на чистой БД.
Проверено обновление на отдельной ext4-файловой системе. Эти проверки не заменяют
первую загрузку IMG и аппаратную приёмку на новой мойке.
