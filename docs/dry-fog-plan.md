# Сухой туман — поэтапный план

Основа: [ТЗ](dry-fog-spec.md). Сейчас выполняется только проектирование. На каждом этапе — отдельная проверка результата; не считать реальные аппаратные/денежные тесты пройденными по unit-тестам.

| Этап | Результат | Проверка перед переходом |
|---|---|---|
| 0. Закрыть правила | VIP, бюджеты паузы по типам, тариф паузы, точный idle-таймер, три рендера | Согласованные решения добавлены в ТЗ; неизвестные цены не подставлены |
| 1. Тип устройства | wash/dry_fog, сохранение конфигурации, совместимость старых постов | Старые настройки читаются как wash; смена типа запрещена при деньгах/сеансе |
| 2. I/O-профиль | aroma_1…5, blackening, tank_air, purge; соответствие backend/helper | Полная карта 0–7, несовпадение профилей блокирует запуск; тесты без GPIO |
| 3. Клиентский engine | Свободный баланс, тарифы семи услуг, запуск без курка, переключение | Не более одного выхода; подтверждённый OFF до ON; при нуле OFF; регрессия мойки |
| 4. Пауза | Включение Owner, 300 секунд на визит, затем платная пауза | Нет автоматического запуска, нет обновления бюджета; отдельная проверка миграции общего кошелька |
| 5. Продувка | Idle scheduler и ограниченный выход №8 на helper | Приход денег/NFC прерывает цикл; fault/reboot/watchdog выключают; нет очереди просроченных циклов |
| 6. /install и состав | Тип/номер/имя, список устройств одной мойки, связь с активацией | 10 wash + 2 dry_fog, дубликаты/чужая мойка/недоступность главного; разные подсети |
| 7. Owner/Admin | Семь режимов, тарифы, пауза, обслуживание, диагностика | Сохранение/чтение, роли доступа, заблокированные опасные изменения, RU/UZ/EN панели |
| 8. Клиентский UI | Реальные HTML/CSS/SVG-компоненты по утверждённым рендерам | UZ/KZ/KY/RU, обе темы, portrait 1080×1920, активные/пауза/ноль/сервис/ошибка |
| 9. Отчёты и Telegram | Типы устройств, фильтры/итоги, технические события продувки | Нет выручки от продувки; primary/standby без двойной отправки |
| 10. Приёмка и golden | Стендовые проверки, отдельный новый заводской профиль | Полный backup/restore; кошелёк/VIP после согласования; чистая карта/уникальная identity; фактическая проверка 32 GB |

Принцип выпуска: не переносить рабочие БД/лицензии стендов в golden image и не менять тип действующей мойки ради теста. Для нового типа нужен отдельный стенд или разрешённая переустановка пустого контроллера. Купюроприёмник, NFC и продувка требуют физической приёмки до ограниченного пилота.
