# Быстрое переключение реле и IN3 — 16 октября 2026

Причины прежней задержки: движок выполнял восемь отдельных HTTP OFF-команд,
helper перед каждым ON повторял восемь Modbus OFF-записей; входы опрашивались
с дополнительным ожиданием 1 секунды. Отдельный замер старого OFF-прохода:
1.179 с без следующего включения.

Изменения:

- Новый `/controller/all-off` подтверждает OFF всех восьми выходов одним HTTP
  запросом. Читается реальная плата; выключаются только включённые выходы,
  затем повторно проверяется полное OFF. Кэш не используется как доказательство.
- Перед ON helper также читает плату, исключая восемь ненужных записей, если
  выходы уже выключены. Порядок OFF → подтверждение → ON сохранён.
- При сбое/неполном readback выполняется прежний полный аварийный OFF. Движок
  сохраняет такой же fallback при недоступном новом endpoint/старом helper.
- Пауза между успешными Modbus-опросами — 50 мс; при ошибках остаётся 1 секунда
  перед повтором. Реальный период также включает время обмена RS485.
- Фоновая публикация состояния выходов синхронизирована с командами, чтобы
  старый снимок не перезаписывал подтверждённый результат переключения.
- Watchdog 2 секунды и heartbeat перед ON сохранены. Скорость RS485 остаётся
  9600 8N1, адрес платы 1; финансовые настройки не менялись.

Проверки: 127 тестов движка и 26 unit-тестов helper прошли. Проверены один/
несколько активных выходов, залипание, сбой записи, неполный readback, отсутствие
лишних записей в покое, совместимость fallback и запрет ON при отсутствии lease.
Ручные диагностические GPIO/PN532-скрипты не относятся к unit-набору; их запуск
параллельно работающему helper конфликтует с занятым GPIO и I2C.

На реальной плате новый all-off в покое подтвердился за 0.107 с. Журнал NV9
остался с 10 импульсами, не сбрасывался. Остаток восстановлен движком; тариф
платной паузы во время обслуживания не изменялся.
