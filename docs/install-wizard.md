# Мастер установки SAMMOY2

Адрес: `/install`. До завершения доступен из доверенной локальной сети через
проверку nginx; после завершения изменение сети/Telegram требует входа в Admin/Owner.

1. **Проверка:** аппаратная идентичность платы и microSD, Modbus I/O; сеть Ethernet,
   Wi-Fi, DHCP или static IP. Настройки сети требуют подтверждения за 90 секунд,
   иначе агент возвращает предыдущие. Несохранённые изменения или ожидающее
   подтверждение блокируют переход дальше.
2. **Активация:** по коду сервера (по умолчанию https://pay.labrix.uz) либо через
   подписанный файл. Номер поста и мойку выдаёт сервер. Если код уже применён,
   повторять его не нужно: кнопка проверки активации обновляет лицензию.
   При повторном открытии активированный пост начинает с проверки активации.
3. **Кошелёк и роли:** явно выбрать общий кошелёк или отложить его. Общий требует
   сохранённых ролей; на всех постах номера основного/резервного должны совпадать.
   Несохранённые изменения запрещают переход. Сохранённые роли не означают, что
   резерв синхронизирован: сверка выполняется отдельно после подключения обоих узлов.
   Отложенная настройка оставляет локальные карты; дальнейший перенос остатков
   должен использовать штатную миграцию.
4. **Запуск:** итоговые данные, повторная проверка готовности, необязательная настройка
   Telegram на главном посте, QR привязки владельца и автопоиск отчётных узлов.
   Замена уже привязанного владельца/бота требует входа Owner.
   После явного подтверждения доступна кнопка открытия `/wash`.

Активация, импорт ответа и завершение запрещены сервером при клиентском балансе,
активном/подготовленном режиме или открытом сеансе. Данные клиента не сбрасываются.
Мастер не включает реле и не начисляет тестовые деньги.

До работы с клиентами: обязательная смена начальных паролей Owner/Admin, аппаратная
приёмка, настроенный резерв и проверка реальных платёжных каналов. Завершение
мастера не является подтверждением полной производственной приёмки.

Проверки: `tests/install.mjs` (mock API, Chromium), `test_install_readiness.py`
(серверные ограничения), регрессия `tests/admin.mjs`. Физическая смена сети и реальная
привязка Telegram требуют проверки установщиком: тесты не меняют сеть действующей платы.

## Сеть заказчика

Блок «Сеть поста» сразу открыт на первом этапе. Доступен DHCP либо постоянный IP
с маской подсети в десятичной записи, шлюзом и DNS. Параметры читаются из текущего
роутера через NetworkManager; привязки к домашней сети разработчика нет.
Каждому посту назначается отдельный адрес, при необходимости резервируется на роутере.
После применения нового IP показывается ссылка для переподключения, подтверждение
ограничено 90 секундами; без подтверждения действует откат NetworkManager.
`/install.` перенаправляется на `/install`.

Видимые названия производителя платы убраны из сети установщика и диагностики Admin.
Это изменение интерфейсных подписей, а не механизм сокрытия аппаратной платформы
от доступа к ОС или техническим API.

Проверки: browser install с сетью 192.168.50.0/23 и собственным DNS, регрессия Admin,
маски /8–/30, серверная валидация 192.168/172.20/10.42. Реальные сетевые профили
пользователя не переключаются этими тестами.
