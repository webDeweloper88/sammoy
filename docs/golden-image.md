# Golden image SAMMOY2

## Текущий этап

Реализованы экспорт чистого приложения, генерация индивидуальных секретов,
сервисы первого запуска и защита от повторной инициализации. Это ещё не готовый
образ ОС: загрузка второй платы, размер 32 GB и мастер установки должны пройти
приёмку перед массовой записью. Ничего из перечисленного не запускается на
действующем посте автоматически.

## Почему не клонировать активный пост

Экспорт `deploy/golden/template.py <новый-каталог-вне-проекта>` не читает живую
`.env` и не переносит `data`, PostgreSQL, журнал NV9, Telegram-volume, резервные
копии, Git-учётные данные и браузерный профиль. Переносятся исходники, assets,
карта I/O и Compose. Пользовательские тарифы/темы из БД пока не экспортируются:
для их переноса нужен отдельный проверяемый профиль без идентичности мойки.

`identity.py` создаёт новые пароли PostgreSQL, Owner/Admin, JWT, ключи Telegram
setup/report API. Пароли начального входа находятся локально в
`factory-access.json` (0600); приложение требует сменить их при входе.
Повторная генерация запрещена при существующей `.env` или непустом `data`.
Пустые каталоги дают новым БД и журналу NV9 создать собственные идентификаторы.

## Порядок сборки на отдельной заводской карте

1. Подготовить базовую ОС Radxa Cubie A7A на карте 32 GB, Docker Compose,
   зависимости host agents и драйверы. Сохранить версию и контрольную сумму ОС.
2. Поместить экспорт в `/opt/sammoy/sammoy2`; заранее загрузить четыре образа
   SAMMOY2 и postgres:16-alpine. Первый запуск использует `--no-build --pull never`.
3. Установить PN532 engine mode, сетевой агент и ограничения журналов; проверить
   порядок запуска. Установить `deploy/golden/install-factory-services.sh`.
4. Подготовить отдельный factory kiosk-профиль с начальным URL `/install`.
   Сеть образа должна использовать DHCP, без IP и Wi-Fi паролей исходной платы.
5. На выключенной заводской системе очистить её machine-id, SSH host keys,
   random seed, DHCP leases и профили браузера. Этот офлайн-шаг ещё не автоматизирован;
   не выполнять его на текущем посте. Заводской образ не содержит личных SSH-ключей,
   сохранённых паролей sudo или истории разработки.
6. Снять образ выключенной карты и проверить размер/хеш. После записи на другую
   карту проверить первый запуск, уникальные machine-id/SSH/JWT/hostname,
   пустой ledger, новый NV9 stream, доступность `/install` и обязательную смену паролей.
7. Активировать отдельным кодом поста той же мойки, настроить роли общего кошелька,
   проверить оборудование и только затем завершить установку.

Сервис identity выполняется до Docker и SSH. Drop-in Requires запрещает их запуск
при ошибке создания идентичности. Маркер снимается только после успешного старта
Compose и доступности API установки. При отсутствии оборудования он остаётся:
можно повторить запуск после подключения устройств. Контейнеры могут уже работать
частично — это не признак завершённой установки.

## Незавершённые проверки

- Автоматическая сборка самой ОС/офлайн-очистка, checksum manifest образов и версия выпуска.
- Доставка начального пароля установщику и удаление handover после смены паролей.
- Сенсорный мастер сети/активации/ролей/Telegram и kiosk autostart с восстановлением.
- Повторные загрузки после сбоя питания во время первого запуска.
- Реальная карта 32 GB, вторая Radxa и испытания репликации/ручного резерва.

Проверка изолированных функций:
`python3 -m unittest discover -s deploy/golden -p 'test_*.py' -v`.
