# Вход Owner по служебной NFC-карте

17 ноября 2026: установлено и запущено на 10.10.10.26. Сервер, интерфейс и PN532 проверены; физический сценарий карта + PIN ещё предстоит проверить пользователю. На Radxa 10.10.10.8 установлены новые образы и пересозданы контейнеры приложения без запуска: до обновления все сервисы были остановлены, оборудование отключено. Миграция БД Radxa выполнится при следующем запуске.

## Регистрация

1. Завершить клиентский/VIP-сеанс: баланс 0, активная услуга выключена.
2. Удерживать логотип главного экрана 6 секунд и войти обычным логином/паролем Owner.
3. Открыть «Учётная запись» → «Служебные карты Owner».
4. Указать название, PIN из 4–12 цифр и пароль Owner. Можно использовать новую либо локальную обычную клиентскую карту без денег. Нажать «Добавить карту».
5. За 60 секунд приложить карту к PN532. После чтения нажать «Сохранить».

Локальную обычную клиентскую карту с нулевым балансом можно перевести в служебную. При сохранении повторно проверяются баланс, незавершённые сеансы/операции и невозвращённые средства. История сохраняется, прежняя платёжная запись отключается и получает тип `service`. VIP-карты и карты с деньгами не переводятся. Карты общего кошелька пока не переводятся даже при нулевом остатке: для них нужна отдельная процедура резервирования на всех постах. При включённом общем кошельке регистрация проверяет карту у главного поста; недоступность кошелька останавливает регистрацию.

## Вход и отзыв

На свободном посту приложить служебную карту. Откроется экран PIN, даже если в браузере был сохранён обычный вход Owner. После правильного PIN открывается управление Owner. Вход по удержанию остаётся доступен.

Пять неверных PIN блокируют карту на 5 минут. Ввод PIN ограничен 45 секундами. Сессия имеет срок 10 минут; экран возвращается к мойке после 90 секунд без действий. Сервер отклоняет сессию после 2 минут без авторизованных запросов. Автоматические запросы могут обновлять серверное время активности, но не продлевают срок токена.

В «Учётной записи» можно отозвать карту с паролем Owner. Все её сессии отклоняются при следующем запросе. Отозванный UID остаётся зарезервированным и не становится денежной картой.

## Права и ограничения

- Серверная сессия содержит `auth_method=password|nfc_pin` и `service_card_id`; карточные сессии также записываются в БД.
- Изменения карт/VIP, кошелька, состава постов, типа устройства, обновлений, системных действий и привязки Telegram требуют пароль Owner при входе по карте. Подтверждение действует 30 секунд, привязано к сессии, HTTP-методу, пути и содержимому одного запроса и расходуется однократно.
- Изменение учётной записи проверяет текущий пароль. После сохранения вход по карте остаётся входом по карте.
- Создание и отзыв служебных карт имеют собственную проверку пароля. Регистрация привязана к конкретной сессии и сроку 60 секунд.
- PIN хранится как Argon2-хеш. События регистрации, отзыва и входа содержат идентификаторы Owner/карты, без PIN, пароля и полного UID.
- Служебная карта перехватывается до клиентского/VIP-кошелька; деньги и денежный сеанс для неё не создаются.
- Реестр локальный: карта служебная только на посту, где зарегистрирована. Автоматической синхронизации между постами пока нет. Использовать отдельную карту, не прикладывать её для оплаты на других постах.
- Несколько процессов wash-engine для этого потока не поддерживаются: краткоживущие ожидания карты/PIN и подтверждения действий находятся в памяти одного процесса. Текущий запуск Uvicorn использует один процесс.
- UID не доказывает подлинность карты криптографически. Защита этого варианта — PIN, ограничение попыток, короткая сессия и подтверждение критичных действий паролем.

## Проверка на стенде

1. Зарегистрировать отдельную пустую карту обычным входом Owner.
2. Вернуться на экран мойки: проверить неверный/правильный PIN и выход без активности.
3. При сохранённом обычном Owner-сеансе приложить карту: должен потребоваться PIN.
4. При ненулевом балансе и в VIP-сеансе карта не должна открывать вход или менять деньги/услугу.
5. Проверить прежнюю обработку обычной клиентской/VIP-карты.
6. Из карточного входа изменить обычный тариф; для критичного изменения кошелька должен появиться запрос пароля Owner.
7. Отозвать карту: проверить отказ действующей сессии и нового входа.
8. Проверить вход по удержанию 6 секунд.

## Автоматические проверки

Backend: `tests/test_service_access.py`. Для PostgreSQL-проверок выставить `SERVICE_ACCESS_TEST_DATABASE=1` и `WASH_ENGINE_POSTGRES_*` только для отдельной тестовой БД: тесты создают схему и очищают таблицы служебного доступа.

Frontend: `node tests/service-access.mjs` проверяет подтверждение/отмену запроса и локализацию ошибок. Production-сборка: `npm run build`. Для стенда не требуется менять прошивку сенсора.
