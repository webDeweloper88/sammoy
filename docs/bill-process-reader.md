# Отдельный процесс чтения GPIO

На Cubie A7A поток чтения внутри общего Python I/O-процесса пропускал целый
50-мс импульс. В контрольной серии независимый наблюдатель увидел 50 импульсов,
основной читатель — 49. Отключение проверки `sampling_gap` не устранило пропуск.

`ProcessLevelReader` опрашивает тот же уже запрошенный GPIO handle через Linux
GPIO v1 ioctl в отдельном процессе каждые 2 мс. Он не запрашивает второй GPIO,
не управляет реле, не обращается к БД и не начисляет деньги. Наблюдения передаются
по ограниченному бинарному каналу; переполнение, обрыв или зависание блокируют
приём. Отсутствующие переходы не восстанавливаются по номиналу купюры.

Включение для проверенного профиля `reader: level`:

```dotenv
IO_BILL_LEVEL_PROCESS=1
IO_BILL_SAMPLER_NICE=-10
```

Compose предоставляет I/O capability `SYS_NICE`; повышенный обычный приоритет
устанавливается только процессу опроса. Realtime-планировщик не используется.
По умолчанию переменные выключены, существующие профили `edges` не меняются.
Изменение режима применяется перезапуском I/O на пустом посту с выключенными
выходами. Смена настроек фильтра через API перезапускает только сам sampler;
GPIO handle, журнал и счётчик сохраняются.

В проверенной установке PC817 устранил короткие помехи. Для фактически
измеренных импульсов около 50 мс выставлены минимальная длительность и пауза
25 мс. Это настройка конкретного оборудования, а не универсальный профиль для
произвольных купюроприёмников. `sampling_gap` и остальные защиты включены.

Контрольная купюра 50 000: 50 наблюдаемых, 50 принятых и 50 записанных импульсов,
баланс 50 000 без бонуса. Затем пользователь проверил разные купюры; к концу
серии наблюдались 200 принятых импульсов без отклонений и неопределённых пауз.
Максимальная пауза опроса за эту серию — около 22,5 мс; тест не доказывает
отсутствия потерь при любой нагрузке или неисправности оборудования.

На тестовом посту 10.10.10.9 режим закреплён в обычной конфигурации запуска.
Источник счётчика и его значение сохранены. Обновление исходников само по себе
не обновляет ранее выпущенный golden IMG: контейнер и настройки необходимо
отдельно включить в следующий выпуск образа и проверить его первую загрузку.
