# Локальная проверка лицензии и работа при недоступности VPS

Новая версия поста запрашивает `authorization_protocol=1` и случайный nonce.
Сервер возвращает Ed25519-подпись над документом
`labrix.license-authorization.v1`: мойка, номер поста, fingerprint контроллера,
время выдачи, nonce и полное решение лицензирования с поколением контроллера
и ревизией отзыва. Публичный ключ проверки поставляется с доверенным образом
приложения; ответ сервера не может заменить этот ключ.

Бессрочная подписанная лицензия не имеет сетевого срока. Срочная действует
до подписанного `valid_until`. Отсутствие интернета, HTTP 5xx, ошибка DNS или
неверная подпись нового ответа не заменяют последнюю проверенную лицензию.
Дата окончания и явный подписанный запрет продолжают действовать локально.
Старая неподписанная запись кеша не превращается автоматически в бессрочное
разрешение: при переходе нужен один успешный обмен либо подписанный файл.
Старые версии постов продолжают получать прежний протокол и 24-часовой lease.

Синхронизация проходит автоматически при старте, затем не реже раза в 15 минут
при стандартной конфигурации; после ошибки повторяется через минуту. Переход
сервера из недоступного состояния в доступное запускает внеочередную проверку.
Отзыв `revocation_pending` сохраняет существующий оплаченный сеанс и запрещает
новые оплаты; подтверждение отзыва отправляется только после освобождения
поста и подтверждённого OFF. Замена контроллера выдаёт старой плате подписанный
запрет. Недоступному серверу невозможно немедленно отозвать офлайн-лицензию.

Время срочной лицензии продвигается монотонным таймером. Максимальная временная
отметка сохраняется в `license_cache.clock_high_water` не чаще раза в минуту;
после перезапуска учитываются эта отметка и часы платы. Свежий ответ с nonce
позволяет восстановить временную опору по подписанному времени сервера.
Для точного учёта времени выключенной платы нужны исправные RTC/питание часов.
Бессрочная лицензия от календарных часов не истекает.

В серверном разделе «Лицензии» администратор может скачать JSON-файл
`labrix.license-file.v1` для уже привязанного поста. На посте он импортируется
через Admin → Лицензия → Подписанный файл лицензии, только в свободном состоянии.
Проверяются подпись, привязка, время выдачи и отсутствие отката ревизии.
Поддерживаются и ранее подписанные файлы первоначальной офлайн-установки
с бессрочным cash-only разрешением.

Click использует отдельную проверку `/health`. Первая обнаруженная ошибка
или устаревшая проверка отключает создание новых платежей на посте. Лицензия,
наличные и локальные программы от этого не блокируются. Для восстановления
доступности нужны два успешных health-check. Существующий QR при потере связи
не показывается для новой оплаты, но платёж не отменяется и не объявляется
неоплаченным только по сетевой ошибке.

Фоновая сверка Click работает независимо от открытой страницы оплаты.
Операция подтверждается серверу только после устойчивой финансовой квитанции.
Повтор экспорта и потеря ACK не зачисляют деньги повторно. Новые платежи связаны
с исходным сеансом, в том числе на самостоятельном посте. Поздняя оплата после
закрытия сеанса сохраняется в recovery, а не передаётся следующему клиенту.
Для неоднозначного создания QR сохраняется предупреждение: второй платёж
автоматически не создаётся.

Проверки: тесты подписи/привязки/отзыва/времени, настоящие маршруты VPS и отдельная
PostgreSQL-база, финансовые интеграционные тесты повторной выдачи и потери ACK,
браузерный `test:licensing`. Производственные платежи в тестах не используются.
