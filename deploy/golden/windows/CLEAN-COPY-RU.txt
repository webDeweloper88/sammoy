LABRIX — очистка отдельной рабочей копии

Распакуйте ВЕСЬ архив в G:\001_sammoy. Запустите 05-CLEAN-COPY.cmd.
Права администратора Windows не требуются. Исходная SD и новая SD не нужны.

Меняется только /var/lib/labrix-golden-build/LABRIX-WORK.img внутри Ubuntu.
Исходный LABRIX-SOURCE-POST2-20261021-121320.img на G: не изменяется.
Скрипт проверяет состояние копии, GPT и хеши нового пакета приложения.
Система из образа не запускается; используется только Python/утилиты Ubuntu.

Из копии удаляются база, лицензия, Telegram, данные карт/денег, старые контейнеры,
профили сети, домашние каталоги, логи, кеши, старые системные пароли и SSH-ключи.
Устанавливаются чистое приложение и проверенные ARM64 Docker-образы.
Сохраняются ОС, драйверы, загрузчик, заставка, поворот экрана и сенсор.
При первом запуске новой платы генерируются новые пароли и идентификаторы.
Ethernet сначала использует DHCP, без адресов постов 1 и 2.
Ключ установщика: только уже переданный публичный ключ. Закрытого ключа в образе нет.
Пароли нового поста будут доступны установщику по SSH в ~/labrix-first-login.txt.

Автоматические резервные копии не включаются. Логи ограничены по размеру.
Исходные финансовые данные на действующих постах не затрагиваются.

После успеха пришлите итоговый текст. При ошибке не повторяйте очистку:
рабочая копия может быть частично изменена. Оригинал остаётся для восстановления.
Это ещё НЕ готовый golden image: очистка свободных блоков, уменьшение образа
и проверка запуска на новой плате выполняются следующими шагами.
